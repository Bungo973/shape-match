# 项目规范（草案 v0.13）

## 玩法与信息

- 玩家做决定前显示敌人的已确定意图、剩余 AP、毒气阈值、催化剂层数和嵌片格位；不依赖隐藏信息制造难度。
- 结算按阶段展示，数字与日志一致。倍率、神器和嵌片的额外值分开标示。
- 以**第一次重力移动**为主动/被动阶段边界。移动前的炸弹爆炸和接力清除按四类方块分别进入基数；移动后的匹配、炸弹生成与引爆只贡献倍率，不产生方块颜色的基础效果，也不触发当前三种普通基数嵌片。火药嵌片连带清除继承触发爆炸的主动或被动来源，不产生计分特例。首版 Boss 即使把重力反转为向上，边界也不变；左右方向仅作为后续扩展预留。详见[特殊方块设计](SPECIAL_TILES.md)与[重力异常设计](GRAVITY_DESIGN.md)。
- 战斗中不高亮推荐交换、不预览主动消除或连锁。任意相邻不同方块交换都会消耗 AP 并保留新排列；普通未匹配交换可用于铺路。所有炸弹均无属性；任意一枚可花 1 AP 单独点燃。五连炸弹与相邻普通方块交换可发动，两枚相邻炸弹即使同类型也可交换发动组合。
- 直线炸弹直接交换的十字、两枚 3×3 炸弹直接交换的 5×5，锚点均取第一枚被选中或拖动的炸弹的落点；点击操作先选的格、拖动操作起点都作为交换来源。结算日志记录交换来源格与目标格，以便复盘正向与反向交换的差异。
- 主动交换产生多个独立匹配组时每组各产一枚炸弹，位置取属于该组的交换方块落点；两枚交换方块的落点需分别记录。被动匹配产弹选当前重力方向最远的匹配格，最远行并列时选最左列。产弹格不计清除，无属性炸弹实体随重力移动，嵌片位置固定。战斗中显示当前向上／向下状态、Boss 预告的向上反转及状态剩余玩家回合数（暂定初始 3）；意图被眩晕取消时，方向预告同步撤销。持续时间在完整玩家回合结束时扣减，不按交换次数扣减。
- 小怪直接奖励是嵌片；神器可从开局选择、两个大怪（精英）、随机事件和商店获得。神器获得后持续生效至本局结束，没有固定持有件数上限；同名不重复。特殊神器可有负面代价，奖励预览必须同屏展示收益与代价；战斗结算要标明来源。
- 神器只按条件自动触发，不提供额外主动施放或爆炸方向选择。毒气控制进度在敌人回合结束时按参数衰减，包括眩晕跳过意图的回合；保留进度的神器须在毒气条旁显示修正结果。
- 战斗分数与金币是两种不同数值，界面和数据模型分别命名；战斗金币暂按敌人类型固定发放，不引用分数或倍率。金币获取、商店购买、消费和事件代价都在确认前显示。
- 仅非战斗阶段可将库存嵌片旋转并嵌入棋盘；战斗中只能查看布局，不能嵌入。嵌入即固定，普通操作不能移动、旋转或取出已安装嵌片。取出仅在第 3、6 战后的商店或明确提供该效果的特殊事件开放；取出后回到随身匣，可再次旋转并嵌入。战后营地升级与休息二选一，普通嵌入不占用选择。
- 嵌片的所有格同效，没有核心格；升级仅增加一个正交相邻覆盖格，不提高单格效果，已安装的原位扩张。嵌片以覆盖范围和简单的局部效果为主要养成方式，稀有度候选见[嵌片设计](INSERT_DESIGN.md)；当前攻击／护盾／毒气的格位基数加成只是普通款原型占位。火药嵌片由被动爆炸触发时，其连带清除仍只提高倍率。
- 规则例外必须写在神器、嵌片或敌人描述里；战斗中遇到例外时给出短提示。
- 先保证规则稳定和可读，再增加随机事件、特效或复杂例外。

- 消除结算按阶段与波次进行，同一波内结果与处理先后无关；动画从爆炸锚点向外扩散，只呈现结算日志，不改变结果。详见[触发引擎与消除结算](INSERT_DESIGN.md#触发引擎与消除结算2026-09-27-已确定)。
- 新的嵌片、神器与敌人效果进入正式池前，必须通过[防卡壳的五条设计规矩](INSERT_DESIGN.md#防卡壳的五条设计规矩硬性审查标准)：消耗原则、不跨阶段存状态、只作用于自身、只用三种动作、五问齐全。

## 可访问性与输入

- 四类基础方块同时用颜色和独立图标/形状区分；四种炸弹均为独立无属性方块，各有能辨认的图标，不伪装成某一种基础方块。状态有文字和数值。
- 目标触控区域至少约 44×44 CSS 像素；键盘可选择相邻格并交换，焦点可见。
- 动画可跳过或缩短；动画进行时不接受重复交换或点燃；结束后立即恢复输入。
- 不用颜色或粒子特效作为伤害、眩晕和嵌片触发的唯一提示。

## 技术栈与目录（2026-09-27 确定）

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 规则引擎 `src/engine/` | TypeScript（严格模式），零运行时依赖；Vitest 测试 | 全部规则与结算，输出新状态与事件日志；不引用任何界面或浏览器 API |
| 战斗舞台 | PixiJS v8（WebGL） | 棋盘、方块、炸弹、嵌片覆盖层、角色与敌人、爆炸扩散、粒子与辉光；按事件日志播放 |
| 界面 | React（DOM） | 状态栏、结算明细、地图、奖励、商店、事件、嵌片调整面板；棋盘上叠透明 DOM 格承担键盘焦点与读屏标签 |
| 动画 | GSAP 与 Pixi 粒子库 | 补间、下落节奏、扩散时序 |
| 构建 | Vite，npm | 纯静态站点，本地存档用 localStorage |

- 引擎先行：规则由测试驱动实现，界面只调用引擎的公开函数。
- 美术原图保留在 `assets/`；进入游戏前用脚本缩放并打包为 WebP 图集，棋盘图标按约 160px（两倍单格）导出。
- 代码标识符用英文，与本文件列出的字段名一致；注释用中文。

## 代码与数据（开始编码时适用）

- 游戏规则为纯状态转换：给定旧状态、玩家动作和随机种子，产生新状态和事件日志。界面只负责展示和发出动作。
- 所有可调数值集中在配置，避免把阈值散落在界面组件内。
- 明确区分 `activeClearsByType`、`passiveClearCount`、`resolutionPhase`、`bombCreated`、`bombTriggered`、`colorBombTargetType`、`baseValues`、`multiplier`、`settlementScore`、`socketBonuses`、`artifactBonuses`、`finalEffects`；所有无属性炸弹都不计入 `activeClearsByType`，但在被动阶段被消耗时计入 `passiveClearCount`。不要以一个“分数”变量承载不同意义。
- 随机数使用可复现种子，包括同色炸弹批量生成直线炸弹时每枚的横/竖方向；存档包含规则版本、当前重力方向和已排定的方向切换。读取旧存档必须迁移或明确提示重开。
- 结算日志是调试、复盘和界面动画的共同数据源，不在动画层重新计算伤害。

## 验证与变更

- 对高风险规则写自动化测试：任意相邻交换、普通未匹配交换的 AP 与状态、同一匹配组满足多种生成条件时的五连 ＞ T/L ＞ 四连优先级、一次交换让两枚参与方块各形成四连并各在自己的落点产弹、向下／向上被动产弹的末端格与并列格选择、产弹格不计清除、同向和异向直线炸弹交换的十字范围及正反方向锚点、两枚 3×3 炸弹交换的 5×5 范围与边缘裁剪、无属性五连炸弹的四类交换组合与随机方向复现、任意炸弹单独点燃与五连随机目标复现、主动/被动炸弹波及五连后的随机目标和来源归类、自然下落生成并引爆炸弹、炸弹接力与同一方块去重、Boss 向上重力异常的预告、眩晕取消、从下边缘补位、按完整回合扣除暂定 3 回合（含提前结束）、生效期间不再选中反转意图与期满恢复、四类主动基数、倍率封顶、旧/新充能、眩晕时机、嵌片重复触发、战斗中嵌入禁用、嵌入后固定、商店/事件取出回库存与再次旋转嵌入、敌人死亡、金币重复发放、神器多来源去重、商店扣款和存档恢复。
- 每次修改公式或时机，同步更新 [GAME_RULES.md](GAME_RULES.md) 的例子和 [PRD.md](PRD.md) 的验收标准。
- 对每个试玩版本记录：规则版本、主要变更、已知问题和固定种子复盘案例。
- 不将“先调大数字”作为解决难度问题的唯一手段；优先判断信息是否清楚、可选行动是否有意义。
